# 🐱 고양이 탭 기획 — 은화 경제 + 고양이집 꾸미기

가계부 활동으로 **은화(코인)** 를 모으고, 그 은화로 **고양이**와 **가구**를 사서
고양이집을 꾸미는 게임화(gamification) 기능. 이 문서는 구현 전 합의용 초안이며,
확정되지 않은 항목은 「결정 필요」로 표시한다. (작업 규칙은 [CLAUDE.md](../CLAUDE.md) 준수)

> 진행 방식: 기존 리디자인과 동일하게 **한 단계씩 완성 → 검증 → 커밋 → 다음 단계**.
> 정적 파일 추가 시 `sw.js`의 `APP_SHELL`+`CACHE_VERSION`, `CHANGELOG`·`code-structure`·`features` 갱신.

---

## 0. 현재 상태 확인 (선행 과제)

- **미션·은화 시스템은 아직 존재하지 않는다.** `public/icons/icon.svg`에 "고양이 은화" 컨셉이
  로고로만 들어가 있을 뿐, 적립·잔액·소비 원장·미션 로직은 전부 신규 구현 대상이다.
- 따라서 이 기능의 실제 1순위는 "고양이 꾸미기 UI"가 아니라 **그 밑을 받치는 은화 경제**다.
- 서버(클라우드 펑션)가 없으므로 모든 판정은 **클라이언트 + RTDB 규칙**으로 처리한다.

## 1. 핵심 개념 정리 (모순 제거)

계획에서 "테트리스처럼 칸에 배치" 와 "고양이가 자유롭게 돌아다님" 이 충돌하게 읽힌다. 다음과 같이 분리한다.

| 요소 | 배치 방식 | 설명 |
|---|---|---|
| **가구/구조물** | 그리드 셀에 **스냅 배치**(테트리스식) | n×n 격자에 물건을 놓는다. 겹침 방지. |
| **고양이** | 격자 위를 **자유 이동하는 액터** | 좌표 고정이 아님. "배치 슬롯 최대 3"은 *어떤 고양이를 집에 내보낼지 활성화*하는 개념. |

즉 **소유(보유 목록) → 활성(집에 내보낸 3마리) → 이동(자유 걷기)** 의 3층 구조.

## 2. 데이터 모델 제안

### 소속: 개인(사용자 전역) — ✅ 확정

- **`users/{uid}/game`** 아래(워크스페이스 무관, 전역)에 저장. 개인↔그룹을 오가도
  내 고양이/은화가 그대로 따라온다. `users/{uid}` 본인 write 규칙이 이미 커버하므로 **RTDB 규칙 변경 불필요**.
- 미션 *진행도 판정*은 현재 워크스페이스의 활동(거래 등)을 읽어 계산하되, *적립 결과(은화·수령 플래그)*는
  전역 `users/{uid}/game`에 기록한다. (읽기=ws 데이터, 쓰기=개인 전역)

### 보유/상태 (RTDB에 저장)

```
users/{uid}/game/
  ├─ coins            : 은화 잔액 (정수)
  ├─ owned/
  │    ├─ cats/{catId}   : { boughtAt }            // 보유 고양이
  │    └─ items/{itemId} : { boughtAt, qty }       // 보유 가구
  ├─ home/
  │    ├─ active/       : [catId, catId, catId]     // 집에 내보낸 고양이(최대 3)
  │    └─ placed/{slotId} : { itemId, x, y, rot }   // 가구 배치(격자 좌표)
  ├─ missions/{periodKey} : { progress, claimed }   // 멱등 수령 (일: 2026-07-01 / 주: 2026-W27)
  └─ ledger/{id}       : { delta, reason, at }       // 은화 증감 원장(선택, 감사용)
```

### 카탈로그(파는 물건 정의)는 **코드 상수**로

- 빌드 도구가 없고 상수는 `constants.js`에 두는 관례를 따른다. 시세·SVG는 하드코딩.
- 예: `CAT_CATALOG`(고등어/치즈/삼색), `ITEM_CATALOG`(가구 3종). 사용자별 저장은 "보유 id"만.

### 보안규칙

- `users/{uid}` 는 **본인 uid만 write** 규칙이 이미 존재 → `users/{uid}/game` 도 그대로 커버됨.
  **DB 규칙 변경 없이** 시작 가능(개인 소속 채택 시).

## 3. 미션 · 은화 경제

### 적립원 (예시 — 「결정 필요: 목록·금액」)

| 주기 | 미션 | 판정 | 보상(예) |
|---|---|---|---|
| 일일 | 오늘 1건 추가 | 그날 `transactions` 또는 `todos`(개인/그룹)에 1건 이상 등록 | +5 |
| 일일 | 출석(앱 접속) | 날짜 롤오버 후 첫 진입 | +2 |
| 일일 | 예산 초과 없음 | 당일 예산 내 | +3 |
| 주간 | 5일 이상 기록 | 주간 기록일수 ≥5 | +20 |
| 주간 | 리포트 확인 | 리포트 탭 진입 | +10 |

### 밸런싱 원칙

- **하루 벌이 vs 고양이 값**의 비율로 "며칠 모으면 한 마리" 감각을 설계.
  예) 하루 최대 ~10은화, 첫 고양이 40~60은화(약 5~7일), 가구 15~30은화.
- 그라인딩(무한 반복 적립) 방지가 밸런싱보다 우선.

### 치팅 방지 (필수)

- **멱등 수령**: `missions/{periodKey}.claimed` 로 "같은 날/주 중복 수령" 차단
  (기존 `recurringLogs` 멱등 로그 패턴 재사용).
- 거래를 넣었다 지웠다 반복해도 재적립되지 않도록 **"수령 완료" 기준은 날짜 키 1회**.
- 타임존은 **KST 기준 자정 롤오버**로 통일(거래 날짜 처리와 일관).

## 4. 상점 · 인벤토리

- 고양이 3종(코숏): **고등어 · 치즈 · 삼색**. 가구 3종부터(흑백 라인).
- 「결정 필요」: **중복 소유 허용?** (같은 종 2마리 / 같은 가구 여러 개).
  - 권장 MVP: 고양이는 종당 1마리, 가구는 수량 허용.
- 구매 흐름: 상점 탭 → 항목 선택 → `coins ≥ price` 확인 → `coins -= price` + `owned` 추가
  (RTDB 트랜잭션으로 원자 처리, 잔액 음수 방지).
- 잔액 부족 시 토스트(기존 `toast()` 재사용).

## 5. 고양이집 화면 (탭 상단)

- **n×n 격자**(MVP는 4×4 정도)에 가구 스냅 배치. 겹침 방지, 빈 칸만 배치 허용.
- 고양이(활성 최대 3)는 격자 위를 **자유 이동**.
  - 구현: DOM transform + CSS transition(3마리·작은 격자면 canvas 불필요).
  - 가벼운 상태머신: idle → walk(랜덤 목적지) → sit/그루밍 → 반복.
- **성능/배터리**:
  - `requestAnimationFrame`은 **화면에 보일 때만** 돌리고, 비가시(`visibilitychange`)·탭 이탈 시 정지.
  - `prefers-reduced-motion: reduce` 면 이동 최소화/정지(정적 포즈). (a11y 레이어 존중)

## 6. 전역 상단 위젯 (앱 진입 시 항상 노출) — ✅ 처음부터 구현

요구: "앱 들어오면 상단에 꾸민 집+고양이가 항상 보인다." → **전역 지속 위젯(cat dock)** 으로 구현.

### 왜 가능한가 (핵심 인사이트)

현재 렌더는 `render*()`가 **`$('content').innerHTML`만** 교체한다. 즉 **`#content` 바깥에 있는 DOM은
리렌더의 영향을 받지 않는다.** 따라서 위젯을 `#content`의 형제로 두면 탭 전환·데이터 갱신에도
**애니메이션이 리셋되지 않고 그대로 유지**된다. 구조 변경은 "위젯 컨테이너 1개 추가" 수준.

### 레이아웃 (flex 세로 스택)

```
header (고정)
#catdock (고정, 접기 가능)   ← 신규. 고양이집 정면뷰 + 걷는 고양이
#content (스크롤, 리렌더 대상)
tabbar (고정)
```

- 고양이 탭은 이 dock을 **크게** 보여주고 그 아래 상점/배치 에디터를 붙인다.
  다른 탭에서는 dock을 **얇게/접힌 상태**로 노출(정보 화면 공간 보호).

### 구현 원칙

- dock은 **부팅 시 1회** 자체 리스너(`users/{uid}/game/home`)를 붙이고 **명령형으로** DOM 갱신
  (리렌더 루프와 분리). `rerender()`는 dock을 건드리지 않는다.
- 이동 루프(`requestAnimationFrame`)는 **보일 때만** 실행: `visibilitychange`·탭 백그라운드·dock 접힘 시 정지.
- `prefers-reduced-motion: reduce` 면 이동 정지(정적 포즈).
- **접기/숨기기 토글**(더보기 설정) 제공 — 화면 공간을 원치 않는 사용자 배려.
- `#catdock`을 `index.html` 셸에 두고, 로직은 `js/cats.js`에서 초기화.

### 주의

- 세로 공간: 480px 폭 모바일에서 상시 dock이 세로를 잠식 → **얇은 스트립(접힘) 기본 + 고양이 탭에서 확장**을 권장.
- dock과 고양이 탭 큰 화면이 **동시에 rAF를 돌리지 않도록** 하나의 애니메이션 소스로 통일(탭이면 확장, 아니면 스트립).

## 7. 디자인 통일 규칙

- **고양이만 컬러**, 나머지(집·가구·UI)는 잉크 모노톤 + 라인 SVG.
- 고양이 색은 앱 토큰(`--income`/`--expense` 등)과 **분리된 일러스트 고유색**으로 정의
  (치즈냥 주황이 지출 레드와 충돌하지 않게). 예: 고등어=쿨그레이 줄무늬, 치즈=웜오렌지, 삼색=흰+주황+먹.
- 가구는 기존 `stroke:currentColor` 라인 아이콘 시스템 그대로 → **다크모드 자동 대응**.
- 격자·집 배경은 `--soft`/`--bd` 톤으로. 그림자/텍스처 최소, 시안 톤 유지.
- 아이콘/일러스트는 **인라인 SVG**(게임 에셋은 base64 대신 SVG가 캐시·성능·다크 대응에 유리).

## 8. 단계별 로드맵 (화면별 완성 방법론)

| 단계 | 범위 | 산출 |
|---|---|---|
| **1. 은화 경제 코어** | 미션 판정 + 적립 + 잔액 + 멱등 수령. UI는 최소(더보기/배지에 잔액·미션 표시) | 경제 시스템 가동 |
| **2. 고양이 탭 셸 + 전역 dock + 상점(고양이)** | 새 탭/라우팅, `#catdock` 지속 위젯 추가, 상점에서 고양이 3종 구매, **1마리 배치 + 걷기** | 고양이 상시 노출·등장 |
| **3. 가구 상점 + 격자 배치** | 흑백 가구 3종, n×n 스냅 배치·겹침 방지 | 집 꾸미기 |
| **4. 최대 3마리 + 꾸미기 심화** | 활성 슬롯 3, 고양이 장착/장식, 상호작용, dock 접기 토글 | 완성형 놀이 |

각 단계 = ① 현재 vs 목표 비교 → ② 구현 → ③ 검증 → ④ 커밋.
전역 dock은 2단계에서 얇은 스트립으로 먼저 세우고, 이후 단계에서 내용(가구·다마리)을 채운다.

## 9. 결정 필요 목록 (합의 후 확정)

1. ~~**은화·고양이 소속**~~ → ✅ **개인 전역(`users/{uid}/game`)**. 규칙 변경 불필요.
2. ~~**배치/이동 개념**~~ → ✅ **가구=격자 스냅, 고양이=자유 이동, 슬롯3=활성화**.
3. ~~**전역 상단 위젯**~~ → ✅ **처음부터 구현**(`#catdock` 지속 위젯, 2단계부터).
4. **미션 목록·보상 금액**: 어떤 활동을, 얼마로. *(다음에 정할 것)*
5. **중복 소유 정책**: 같은 고양이 종/가구 다중 소유 허용 범위. *(권장: 고양이 종당 1, 가구 수량 허용)*
6. **격자 크기**: n(예: 4×4) 및 고양이 이동 반경.
7. **탭 자리**: 5탭으로 늘릴지(현재 4탭+FAB), 더보기 진입으로 둘지.
8. **주 시작 요일/롤오버 타임존**: 주간 미션 판정 기준(KST, 월/일 시작).
