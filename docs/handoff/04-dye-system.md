# 04 — 염색(염색약) 시스템

> eggarden의 펫 염색 기능 전체. 원본: `public/js/cats.js` 3189~3357행(카탈로그·로직), 렌더 적용은 액터/썸네일/펫정보/친구캠/PiP에 분산.
> 핵심 아이디어: **픽셀 재채색이 아니라 CSS `filter` 문자열 하나로 전신 틴트** — 어떤 스프라이트든 코드 한 줄로 염색되고, 원본 자산은 그대로다.

---

## 1. 색 적용 원리 — "절대색" 필터 체인

```css
/* 유채색 */  filter: grayscale(1) sepia(1) saturate(S) hue-rotate(Hdeg) brightness(B);
/* 무채색 */  filter: grayscale(1) brightness(B);
```

- `grayscale(1) sepia(1)`이 스프라이트를 **기준색(골드브라운)으로 정규화** → 이후 `saturate/hue-rotate/brightness`로 원하는 **절대색**으로 이동.
- **명암·외곽선(루미넌스)은 보존**된다 — 도트의 음영·외곽선이 살아있는 채로 색만 바뀜.
- 원본 팔레트와 무관하게 **어떤 펫이든 같은 색으로 일관 염색**되는 게 이 방식의 최대 장점(hue-rotate 단독은 원본색에 따라 결과가 제각각).
- 파라미터(h/s/b)는 CSS 필터 행렬을 파이썬으로 재현한 스와치 시트를 렌더해 눈으로 검수 후 확정(색이 200종쯤 되면 자동화 필수).
- 채도를 낮추면 뮤트톤, 명도를 낮추면 다크톤 — 파라미터 2개로 톤 계열 확장이 쉽다.

### 단일 소스 함수

```js
function dyeFilterCss(v){
  // 문자열 id     → DYE_MAP[v].css (카탈로그의 완성 필터 문자열)
  // 숫자(legacy) → 'hue-rotate(Ndeg)' (화이트리스트 검사)
  // 무효/미염색  → '' (필터 없음 = 원본색)
}
```

**모든 렌더러(캠 액터·썸네일·도감·뽑기 리빌·친구 캠·PiP)가 이 한 함수를 공유**한다. 새 렌더 경로를 추가하면 반드시 이 함수를 거치게 하는 것이 규칙.

---

## 2. 데이터 모델

```js
// 저장: 펫당 필드 1개
game.owned.pets[petId].dye = 'rose_pink'   // 카탈로그 색 id
// 해제: delete pet.dye  → dyeFilterCss('') → 원본색

// 소비 아이템 2종
{ id:'dye',         name:'염색약',  price:금화100 }   // 사용 → 랜덤 색 뽑기
{ id:'dye_remover', name:'리무버',  price:금화200 }   // 사용 → 원래색 복원(무료 해제 없음)
```

- 읽기는 정규화 함수(`petDyeOf(id)`)를 거침: 카탈로그 id 존재 확인 / legacy 숫자 화이트리스트 / 무효 → 0. **저장값 검증을 읽기 시점에 하는 패턴**이라 잘못된 값이 렌더를 깨지 않는다.
- 소비 카운터(`consum.dye` 등)는 상태 정규화 함수에 반드시 등록(필드 유실 방지 규칙).

### 색 카탈로그 — 등급 있는 뽑기 풀

```js
// 생성 헬퍼: C(id, name, group, h, s, b) 유채 / A(id, name, b) 무채 — 총 ~200색
// 등급: rare 셋 / uncommon 셋 지정, 나머지 common
const DYE_TIER_P = { rare:0.03, uncommon:0.29, common:0.68 };

function rollDye(cur){
  // 1) DYE_TIER_P 확률로 tier 선택
  // 2) 그 tier 안에서 균등 랜덤 (현재 색 제외 — 같은 색 재뽑기 방지)
  // 3) tier가 비면 전체 폴백
}
```

**설계 포인트**: 염색약을 "색 선택권"이 아니라 **"색 뽑기"**로 만들어 소비 아이템에 가챠 재미를 부여. 희귀 색이 나오면 리무버를 아끼고 유지하는 심리. 새 게임에서 색 직접 선택 UI를 원하면 rare 색만 뽑기로 남기고 common은 선택제로 하는 절충도 가능.

## 3. 적용 범위 — "한 군데도 빠뜨리지 않기"

염색이 반영되어야 하는 모든 화면과 방식:

| 화면 | 적용 방식 |
|---|---|
| 캠 액터(걷기) | 액터 요소에 `filter:` 인라인 |
| 정면 썸네일(그리드·도감·상점·뽑기 리빌) | `<img>` 에 `style="filter:…"` |
| 펫 정보 히어로 | 동일 인라인 |
| 친구 방(다른 유저에게 보이는 과시) | 방 스냅샷 메타에 `dye` 포함 → 스냅샷 렌더가 명시 전달 |
| **비디오 PiP** | 워커 `ctx.filter`는 신뢰 불가(모바일 GPU에서 무시) → **메인 스레드 canvas에서 비트맵에 필터를 미리 베이크** 후 워커로 transfer |
| 모자·버디(코스메틱) | **미염색**(정책: 염색은 몸만) — 렌더 계층을 분리해 두었기에 가능 |

**재렌더 트리거**: 펫의 코스메틱 서명(`cosmSig = hat.buddy.dye`)에 dye를 포함시켜, 염색 변경 시 캠·PiP가 그 펫만 리빌드. 서명에 안 넣으면 "염색했는데 캠에 반영 안 됨" 버그.

---

## 4. UI 흐름

```
가방에서 염색약 '사용' → 펫 그리드 시트(전 펫 썸네일, 현재 염색 상태 칩)
  → 펫 탭 → 트랜잭션(카운터 -1 + rollDye + pet.dye 커밋) → 결과 토스트("<색이름>!")
  → 시트를 닫지 않고 갱신 — 바뀐 색을 그 자리에서 확인
리무버: 같은 시트 재사용, 필터만 "염색된 펫만" — 메타 테이블(PET_USE_META)로 시트 하나를 여러 소비템이 공유
```

- 펫 정보 화면에서도 진입 가능(소비템 버튼 → 대상 펫 고정 사용).
- 적용은 트랜잭션: 카운터 차감과 dye 커밋을 원자적으로(연타·멀티기기 이중 소비 방지).

---

## 5. 이식 체크리스트

- [ ] `dyeFilterCss` 단일 소스 + 유채/무채 2공식 채택
- [ ] 스와치 자동 렌더 검수 도구(필터 행렬 재현) — 색 확정 전 눈 검수
- [ ] 저장은 펫당 필드 1개, 해제=필드 삭제, 읽기 시 정규화·검증
- [ ] 색 카탈로그 + 등급 뽑기(`rollDye`) — 게임 경제에 맞게 확률 조정
- [ ] 적용 범위 표를 만들어 렌더 경로 전수 반영(특히 스냅샷·PiP 베이크)
- [ ] 코스메틱 서명에 dye 포함(라이브 반영)
- [ ] 소비는 트랜잭션(카운터+커밋 원자화)

**전투 게임 확장 아이디어**: 같은 필터 체인으로 ▸ 손님(적) 진영 표시 틴트(적=붉은 계열 라이트 틴트) ▸ 피격 플래시(`brightness(1.6)` 수십 ms) ▸ 상태이상 표현(독=greenish, 빙결=desaturate+blue) 을 자산 추가 없이 구현할 수 있다. 단, 상시 틴트(염색)와 순간 이펙트 필터가 겹칠 때는 **필터 문자열을 합성하는 단일 헬퍼**(`combinedFilter(pet) = dye + status + flash`)를 두어 서로 덮어쓰지 않게 할 것.
