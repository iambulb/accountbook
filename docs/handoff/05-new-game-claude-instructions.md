## 1. 아키텍처 원칙 (eggarden에서 검증된 것 — 이식 시 그대로 채택)

1. **원근·격자 상수는 단일 소스 객체 하나**(`CAM`)에 모으고, 모든 무대·모든 렌더 경로가 공유한다. CSS 변수와 JS 상수의 정합은 단위 테스트로 잠근다. **무대별 원근 분기 금지.**
2. **순수 로직과 렌더를 분리**: 충돌 판정(`areaFree`)·정규화(`normRoom`)·원근 수식(`camDepth`)·**전투 판정(`resolveBattle`)·부재중 시뮬(`simulateAway`)·방 점수(`roomScore`)** 는 DOM 비의존 순수 함수 → 단위 테스트 대상. 상호작용·렌더는 그 위의 얇은 층.
3. **상태 정규화 함수의 필드 유실 방지**: 게임 상태를 통째로 재생성하는 정규화 함수가 있다면, 새 최상위 필드(재화·카운터)를 추가할 때 반드시 그 함수에 방어값과 함께 등록. 미등록 필드는 다음 쓰기에서 영구 삭제된다(eggarden 실제 사고).
4. **재화는 단일 획득/소비 접점**: `grantX`/`spendX` 두 함수로만 가감 + 누적획득·누적소비 기록 → 자가복구 불변식. 직접 `-=` 금지.
5. **쓰기 경합은 트랜잭션 + 안 재검증**: 배치·소비·보상 지급(전투 드랍·부재중 정산 포함)은 트랜잭션으로, UI 1차 검증과 별개로 안에서 전부 재검증. 대상은 인덱스가 아닌 안정 id로. **드랍 수령은 멱등**(수령 id로 이중 지급 차단).
6. **XSS**: 사용자 입력은 이스케이프 후 삽입.
7. (전역 함수 패턴일 경우) top-level 초기화에서 뒤에 로드되는 파일의 함수 호출 금지(ReferenceError→TDZ 연쇄).

## 2. 레이어 아키텍처 (확정 — 06 §1)

```

② 바닥   : 격자 점유 겸 "이동 가능 맵". placed { "x_y": {itemId,w,h} }. 점유 타일 = 통행 불가/상호작용
③ 벽     : 별도 1~2줄 그리드, 충돌 없음, 장식 전용. 바닥 점유맵과 섞지 말 것
④ 액터   : 펫·손님·FX·드랍 — 연속 픽셀 좌표(rAF). 그리드는 읽기만. 전투는 여기서

- **스폰존 예약(필수)**: 입구 근처 2×2~3×2 타일은 가구 배치 금지 — `areaFree`에서 차단 + 에디터에 표시. 이유·예외(깔개)는 06 §1.
- 배치 시스템 세부(격자 좌표계·트랜잭션·롱프레스 드래그·벽 앵커 3종)는 `01-room-layout.md`. 가구 카탈로그에는 렌더 메타뿐 아니라 **`anchor`(사용 지점)·`action`(재생 동작)·`buffs`·`theme`·`summon`**(06 축1)까지 모으고 정합 테스트를 둔다.

## 3. 캠 렌더링·액터 엔진 → `01`·`02` 참조

- 원근 세트(바닥 54%/벽 46%/무대 58%/rise 0.53)는 한 묶음 — 그대로 채택 권장. 깊이 z(`camZ`)로 펫·가구 상호 가림이 내장(=Y-sort). 원근 없는 top-down이면 y기반 z-index 정렬로 대체하되 반드시 넣는다.
- 무대 DOM 레이어 구조·서명 가드 라이브 패치·절전 계층(reduced-motion/lite/백그라운드/오프스크린)은 02 문서 그대로.
- **불변식: 액터 비주얼 전환은 `actorShowMoving`/`actorShowStill` 두 함수로만. 정면 이미지로 이동 금지.** 전투 상태(SCUFFLE 등)를 추가해도 이 두 함수를 거친다.
- 걷기 주기는 이동 속도 연동(발 미끄러짐 방지), 발밑 여백 실측, 펫 표시 크기는 `effPetScale` 단일 소스.
- 가구 상호작용은 anchor/action 데이터 주도 스케줄러("빈 anchor 찾기→걸어가기→동작 재생")로 일반화 — 가구별 하드코딩 금지.

## 4. 손님·전투·방치 → `06` 이 단일 소스 (요약만)

- **손님 = 임시 액터**(`kind:'guest'`): `enter → wander → event(선물|전투|의뢰) → leave`. 카탈로그 데이터 주도.
- **전투 상태기계**: `WALK → APPROACH(가구 goal 로직 재사용) → SCUFFLE → RESULT → REST`. 새 엔진 금지 — 기존 배회 엔진 확장.
- **연출 = 기존 자산 + 범용 FX 시트 1세트**(먼지구름 4프레임·별·땀·"!"·코인). 투닥은 밀착+흔들림+먼지구름 가림(펫별 공격 모션 불필요). 승리=점프 2회, 패배=도망/belly. **전용 공격 모션은 보스/엘리트(96~168px 대형)만.**
- **판정 선확정**: `resolveBattle(스탯, seed) → {winner, rounds, drops}` 순수 함수. 연출은 재생 전용, 스킵·중단 안전.
- **드랍**: 종료 위치 근처 빈 타일에 상자/코인 스폰 → 탭 수령(멱등).
- **방치 코어**: 접속 시 `simulateAway(lastSeenAt, now, seed)` 결정론 시뮬 → 이벤트 타임라인 → 일괄 정산. 누적 상한 8~12h. 시드는 `f(uid, lastSeenAt)` 고정.

## 5. 고도화 4축 → `06 §5` (우선순위 확정)

1. **배치의 전략화(최우선)**: 가구 버프 + 인접 시너지 + 세트 효과 + 손님/보스 소환 조건. `roomScore()` 순수 함수, 배치 UI에 효과 표시.
2. **부재중 타임랩스 리플레이**: 시뮬 타임라인을 캠에서 배속 재생 + 스킵(보상은 선확정이라 스킵 안전). 텍스트 로그로 끝내지 말 것.
3. **살아있는 방**: 실시간 낮/밤(CSS 오버레이·야행성 손님) · 날씨 FX(bgfx 인프라 재사용·날씨 한정 손님) · 흔적 수거(발자국·털뭉치 → 탭 수거, 드랍 인프라 공유).
4. **카메라(폴리싱)**: 핀치 줌+팬·펫 팔로우캠·포토 모드(canvas 캡처). 방 확장·친구 방·파견은 v2.

## 6. 비디오 PiP → `03` 참조 (해당 시)

- 워커 + OffscreenCanvas + `MediaStreamTrackGenerator` push 경로(모바일 백그라운드 지속의 관건), origin-clean 제약, CSS↔워커 "짝 맞춤" 전사 테이블, iOS 게이트.
- **전투·이벤트 연출의 PiP 반영은 후순위** — 초기엔 PiP에서 배회만(문서화된 예외로 명시).

## 7. 염색 → `04` 참조

- `grayscale(1) sepia(1) saturate() hue-rotate() brightness()` 절대색 체인, 단일 소스 `dyeFilterCss`, 펫당 필드 1개, 등급 뽑기.
- **상시 염색과 순간 이펙트(피격 플래시·상태 틴트)를 합성하는 단일 필터 헬퍼**를 둘 것 — 전투 연출과 겹칠 때 서로 덮어쓰지 않게.

## 8. 픽셀 아트 규칙

- **게임 요소(펫·손님·가구·아이템·FX·연출)는 전부 도트.** 기능 UI는 라인 아이콘 분리 가능. 이모지·벡터 글로우 대체 금지.
- 도트는 문자 매트릭스 + 팔레트 → crispEdges SVG(`pxSvg` 패턴). 비트맵은 `image-rendering:pixelated`. 반복 타일 배경은 canvas→PNG data URI(SVG data URI는 회색 화면 버그).
- 품질 기준: 소품 ≥16~20행, 구조물 24~36행, 4톤 음영+외곽선, 맨 윗줄 비움, 투명화=팔레트에서 글자 제거.
- 연출: 단조 1축 왕복 금지(다층 모션·위상 어긋나게), base+fx 2겹 + 구멍 금지 규칙(02 §3-5).
- **FX 시트(먼지구름·별·땀 등)도 같은 기준** — 확정 전 PIL 렌더로 라이트/다크 배경 눈 검수, 정합 감사 스크립트 상시 운용.

## 9. 자산 파이프라인

- 펫/손님 스프라이트는 단일 레지스트리(json) → 코드·캐시 목록·문서를 스크립트로 재생성(@gen 마커). 코드젠 영역 수기 수정 금지.
- 걷기 시트는 반드시 옆(east) 프레임. east 없으면 `frontWalk` 플래그. 프레임 수 가변(메타 기록).
- 클립 스키마 `{dir, fps, once, hold, fb:[폴백체인]}`. once는 마지막 프레임 수동 프리즈. 클립 보유 여부로 상호작용·해금 자동 연결(하드코딩 금지).
- 보스/엘리트 전용 모션도 같은 파이프라인에 태운다(별도 경로 금지).

4. 연출 도중 판정 계산 금지 — 시작 시점 선확정, 연출은 재생 전용.
5. 부재중 결과를 텍스트 로그만으로 끝내지 말 것 — 타임랩스 리플레이(+스킵 필수).
6. 배경(벽지/바닥재)에 그리드·배치 개념 금지 — 스킨 키 2개.
7. 스폰존에 가구 배치 허용 금지 — 판정·에디터 양쪽 차단.
8. 방 확장·친구 방·파견을 v1에 넣지 말 것.
9. 가구별 상호작용·버프 하드코딩 금지 — 카탈로그 데이터 주도.
10. 새 배회/전투 엔진 신설 금지 — 기존 액터 상태기계 확장.

## 11. 반복 버그 방지 체크리스트 (eggarden 실사고 기반)

1. 원근 상수를 무대별로 갈라놓지 않았나 (단일 CAM)
2. props/stage 컨테이너에 z-index를 주지 않았나 (상호 가림)
3. 깔개를 DOM 맨 앞에 그렸나 (z0끼리는 DOM 순서)
4. 정면 이미지로 이동하는 경로가 생기지 않았나 (2함수 불변식)
5. 데이터 틱마다 innerHTML 재생성하지 않나 (서명 가드)
6. 새 상태 필드를 정규화 함수에 등록했나 (필드 유실)
7. 재화를 grant/spend 접점 밖에서 직접 가감하지 않았나
8. 쓰기(배치·소비·보상·드랍 수령)를 트랜잭션+멱등으로 했나
9. 새 애니메이션(FX·날씨·낮밤 오버레이 포함)을 절전 계층 전부에 등록했나
10. footprint와 렌더 높이를 짝으로 조정했나
11. 연출 move 글자 자리에 구멍이 없나 (bg 치환/감사 스크립트)
12. CSS 연출을 고치고 PiP 전사 테이블을 빠뜨리지 않았나
13. 새 렌더 경로가 dyeFilterCss/effPetScale 단일 소스를 타나
14. 카탈로그·매트릭스·팔레트를 같은 커밋에 넣었나 (정합 테스트 실행)
15. 캐시 버전을 올렸나 / 문서를 같이 갱신했나
16. 판정 순수 함수에 시드를 넣어 재현 가능한가 (테스트)
17. 스폰존·이동 차단이 배치 판정과 액터 경로 양쪽에 반영됐나

① 바닥 그리드 + 점유맵(이동 차단) + 스폰존 예약   ← 데이터 모델 확정 최우선
② 방문객 시스템(전투 없음: 등장·구경·선물·퇴장)    ← 등장/퇴장/이동 인프라 = 전투의 전제조건
③ 범용 FX 시트 + 투닥 연출 (기존 전투 연출을 이 톤으로 개편)
④ 판정 로직(resolveBattle) + 드랍 수거 + 부재중 결정론 시뮬
⑤ 보스/엘리트 티어
⑥~⑨ 고도화 4축: 배치 전략화 → 타임랩스 리플레이 → 흔적·낮밤·날씨 → 줌/팔로우캠·포토
```

각 단계마다: 순수 함수 테스트 추가 + 문서 갱신 + 절전/성능 확인. 렌더 기반(①~②)이 안정되기 전에 전투 개편(③~⑤)을 얹으면 원근·가림·상태기계 버그가 전투 버그와 섞여 디버깅이 불가능해진다.
