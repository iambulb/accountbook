# 06 — 게임 디자인 확정안: 손님·전투·방치 루프와 고도화 4축

> **이 문서는 사용자(운영자)가 확정한 설계 방향이다.** 구현 시 이 문서가 01~05보다 우선한다(충돌 시 이 문서를 따르고, 기술 세부는 01~04 참조).
> 전제: 대상 앱은 **전투가 이미 구현된 기존 방치형 게임**이다. eggarden의 방꾸미기·배치·기구물 상호작용·캠 실시간 렌더를 이식하고, 아래 방향으로 게임 루프를 완성한다.

---

## 0. 설계 철학 (한 문장씩)

1. **전투는 "배치칸에서"가 아니라 "배치칸 위에서"** — 그리드는 데이터(점유·이동 판정), 전투·이동은 액터 레이어(연속 좌표).
2. **전투 톤은 투닥거림(놀이싸움)** — HP바·피격·죽음 연출 금지. 먼지구름+별 만화식 연출로 코지한 정체성 유지. (기존 앱에 구현된 전투 연출이 이 톤과 다르면, 이 톤으로 개편하는 것이 이번 개선의 일부다.)
3. **판정과 연출의 분리** — 승패·드랍은 전투 시작 시점에 스탯+시드 RNG로 확정(순수 함수), 애니메이션은 결과를 보여주는 껍데기. 연출 도중 앱을 꺼도 결과 불변.
4. **배치는 장식이 아니라 전략** — 가구가 버프·시너지·소환 조건을 갖는 순간 꾸미기가 게임플레이가 된다.
5. **방치 보상은 "숫자 지급"이 아니라 "방에서 일어난 일"** — 결정론 시뮬레이션 + 캠 타임랩스 리플레이 + 바닥에 떨어진 걸 줍는 행위.

## 1. 레이어 아키텍처 (확정)

| 레이어 | 역할 | 데이터 |
|---|---|---|
| ① 배경 | 스킨만. **그리드 없음** | `{ wallpaperId, floorId }` 키 2개로 끝. 배치 개념을 넣지 말 것 |
| ② 바닥 그리드 | 가구 점유 **겸 이동 가능 맵** | `placed: { "x_y": { itemId, w, h } }` (좌상단 앵커 footprint) |
| ③ 벽 | 별도 1~2줄 그리드, **충돌 없음**, 장식 전용 | `wallPlaced` — 바닥 점유맵과 섞지 말 것 |
| ④ 액터 | 펫·손님·FX·드랍 — 연속 픽셀 좌표, rAF 루프 | 그리드를 읽기만 함(점유 타일 회피·anchor 접근) |

- **바닥 그리드의 이중 역할(신규)**: 점유된 타일 = 펫·손님이 통과 못 하는(또는 상호작용하는) 타일. 액터 레이어가 이 점유맵을 읽어 이동 경로·전투 위치를 정한다. eggarden은 통행 차단이 없었으므로 이식 시 **추가**해야 하는 부분.
- **원근/Y-sort**: eggarden의 CAM 원근 세트(02 문서)를 쓰면 깊이 z(`camZ`)로 펫·가구 상호 가림이 **내장**된다. 원근 없는 top-down이라면 y좌표 기준 z-index 정렬(Y-sort)로 동등 효과 — 어느 쪽이든 반드시 넣는다(화면 밀도를 확 올리는 저비용 항목).

### 스폰존(무대) 예약 — 필수 규칙

- **입구 근처 2×2~3×2 타일은 가구 배치 금지 구역**으로 예약한다. `areaFree`(충돌 판정)에서 차단하고, 배치 에디터 격자에 시각적으로 표시한다.
- 이유: 유저가 방을 꽉 채우면 방문객이 등장할 곳도 투닥거릴 공간도 없어 전투 시스템 전체가 깨진다. "예쁘게 꾸밀수록 전투가 안 보이는" 역인센티브를 원천 차단하는 장치.
- 깔개(`floor:true`)는 스폰존 위에도 허용 가능(점유가 아니므로) — 단 이동 차단 가구는 불가.

### 가구 상호작용 일반화

- 가구 메타데이터에 `anchor`(사용 지점 좌표·방향)와 `action`(재생할 동작, 예: 캣휠→run)을 넣는다. 행동 스케줄러는 "빈 anchor 찾기 → 걸어가기 → 동작 재생"으로 **일반화** — 가구별 하드코딩 금지. (eggarden `furnSpot`의 `{lift, face, dx, pose, dur}` 패턴이 원형, 01 문서 참조.)

## 2. 손님(방문객) 시스템

- **손님 = 임시 액터**: 주민 펫과 같은 액터 구조에 `kind:'guest'`. 같은 원근·이동·비주얼 불변식을 타므로 캠·염색·크기 압축이 전부 자동 적용.
- **상태기계**: `enter(입구 스폰존에서 걸어 들어옴) → wander(구경·가구 상호작용) → event(선물 | 전투 | 의뢰 중 택1) → leave(걸어 나감)`. 전이 확률·머무는 시간은 손님 카탈로그 데이터가 결정(하드코딩 금지).
- **손님 카탈로그**: 펫 카탈로그와 같은 스키마(스프라이트·scale·tier·클립) + `{ combat:{atk,def,spd…}, dropTable, eventPool, summonReq:[가구 id], activeHours, weather }`.
- **소환 조건(축1과 연결)**: 특정 손님(보스 포함)은 특정 가구가 있어야만 온다 — "고급 방석을 놔야 구미호가 방문". 가구 수집 = 콘텐츠 언락. 보스 소환 제단 같은 전용 가구도 자연 파생.

## 3. 전투 — 투닥거림 설계

### 상태기계 (기존 배회 엔진의 확장 — 새 엔진 금지)

```
WALK → APPROACH(상대에게 접근 — 가구 goal 로직 재사용) → SCUFFLE(투닥) → RESULT(승/패 포즈) → REST/leave
```

### 연출 레시피 (스프라이트 제약 반영 — 핵심 레버리지)

수십~수백 종 펫에 공격 모션을 만들 수 없다는 제약을 **범용 FX 오버레이 1세트**로 해결한다:

| 단계 | 연출 | 필요 자산 |
|---|---|---|
| 접근 | 기존 걷기(옆모습 + flip) | 없음 |
| 투닥 | 두 스프라이트 밀착 + 좌우 흔들림(transform) + **먼지구름 FX 1장이 몸을 반쯤 가림** → 펫별 모션 불필요 | FX 시트 |
| 승리 | 점프 2회(CSS transform 파생) | 없음 |
| 패배 | `scaleX(-1)` 도망 걷기 또는 배 깔고 눕기(belly 클립) | 없음 |
| 보스/엘리트 | **스페셜 티어 대형 스프라이트(96~168px)**, 화면 가장자리 등장. 이들만 전용 공격 모션 제작 → "보스전만 화려한" 자연스러운 티어 차별화 | 보스별 소량 |

- **범용 FX 스프라이트시트 1세트가 전체 전투 연출을 커버한다**: 먼지구름 4프레임·별⭐·땀방울·"!"·코인 반짝. 도트로 제작, `steps()` 재생, 액터 레이어에 오버레이. (도트 제작 규칙은 02·05 문서의 픽셀 아트 기준을 따름 — PIL 검수 포함.)
- 피격 강조가 필요하면 `brightness()` 순간 플래시(04 문서 필터 합성 헬퍼)까지만 — 피 이펙트·HP바 금지.

### 판정 (연출과 완전 분리)

- 전투 시작 시점에 `resolveBattle(내 펫 스탯, 손님 스탯, seed) → { winner, rounds, drops }` **순수 함수**로 확정. 단위 테스트 대상.
- 연출은 이 결과를 재생만 한다. 연출 스킵·배속·탭 전환·앱 종료에도 결과 불변 — 방치형의 필수 조건.
- 보상 지급은 트랜잭션 + 재화 단일 접점(05 문서 §1).

### 드랍

- 전투 종료 위치 **근처 빈 타일**에 상자/코인 스프라이트 스폰 → **탭해서 수령**(멱등 지급 패턴 — 이중 수령 방지 id). eggarden의 바닥 드랍(`drops`, 최대 개수 상한) 인프라 재사용.

## 4. 방치 코어 — 서버 틱 없는 결정론 시뮬레이션

정적 호스팅 PWA 전제(서버가 시뮬레이션을 못 돌림):

- **접속 시 경과시간 기반 결정론 시뮬레이션**: `simulateAway(lastSeenAt, now, seed, 방 상태) → 이벤트 타임라인 [{t, type, guestId, pos, result, drops}]`. 시드는 `f(uid, lastSeenAt)` 고정 — 재계산해도 같은 결과(일관성·치팅 억제).
- 결과는 "부재중 소식"으로 보여주고 보상 일괄 지급. **누적 상한 8~12시간**으로 인플레 방지.
- 방문 확률·등장 손님은 방 상태(가구·점수·시간대)의 함수 — 축1과 연결.
- 푸시 알림("호랑이가 나타났어요!")은 이후 단계에서 Cloud Functions 등 서버 훅 추가.

## 5. 고도화 4축 (우선순위 확정)

### 축1 — 배치의 전략화 (최우선)

꾸미기가 순수 코스메틱이면 초반 이후 동력이 죽는다. **배치 자체가 스탯이 되어야** 전투와 붙는다.

- **가구 = 패시브 버프**: 캣타워=아군 회피 +2%, 밥그릇=방치 코인 +5% 등. 카탈로그에 `buffs:[{stat, val}]`.
- **인접 시너지**: 창가 옆 캣타워=추가 보너스. 점유맵이 있으니 인접 판정은 공짜. 같은 테마 가구 3개=세트 효과(`theme` 태그). "테트리스식 스냅"이 진짜 퍼즐로 승격.
- **소환 조건**: §2 참조 — 특정 가구가 특정 손님/보스를 부른다.
- **방 점수 계산은 순수 함수**: `roomScore(placed, catalog) → { buffs, synergies, summonPool }` — 배치 변경 시마다 재계산, UI에 효과 표시(유저가 "예쁜 배치 vs 효율 배치"를 고민하게).

### 축2 — 부재중 타임랩스 리플레이 (차별화 정점)

- 텍스트 로그를 버리고, **부재중 이벤트 타임라인을 캠 화면에서 배속 재생**한다. 결정론 시뮬(§4)이라 타임라인이 이미 데이터로 존재 — 액터 레이어에 스크립트 재생만 하면 됨. "어젯밤 여우가 침입해 투닥거리다 도망갔고, 새벽에 손님이 선물을 놓고 갔다"를 유저가 눈으로 본다.
- **스킵 버튼 필수** + 보상은 재생과 무관하게 이미 확정(스킵 안전). 구현 비용 대비 임팩트 최대 항목.

### 축3 — 살아있는 방

- **실시간 낮/밤**: 실제 시간(KST)에 따라 방 조명 변화 — CSS 오버레이 그라데이션 + filter로 충분(에셋 불필요). 밤엔 펫 수면, **야행성 손님·밤 한정 보스** → 접속 시간대 분산.
- **날씨/계절 FX**: 비·눈 파티클 오버레이(eggarden 배경효과(bgfx) 인프라 그대로 — 02 문서 §6) + 날씨 한정 손님.
- **흔적 시스템**: 펫 활동이 발자국·털뭉치·물어온 선물을 바닥에 남김 → **탭 수거**(소재/재화). 방치 보상을 "줍는 행위"로 바꿔 접속마다 방을 둘러보는 습관 = 리텐션 훅. 드랍 인프라(§3) 공유.
- **Y-sort/깊이 가림**: §1 참조 — 이미 원근 세트에 내장이거나 몇 줄로 추가.

### 축4 — 카메라·공간 확장 (폴리싱, 후순위)

- 핀치 줌 + 팬, 펫 탭 시 **팔로우캠**("캠"이라는 컨셉을 문자 그대로).
- **포토 모드**: 현재 화면 canvas 캡처 + 프레임/필터 → 저장·공유(소셜 유입 장치, 구현 간단).
- 방 확장(마당→거실→옥상), 친구 방 방문/펫 파견 — **v2 이후**. 방 하나의 밀도를 먼저 채운다(공간 확장은 콘텐츠 고갈 때 꺼내는 카드).

## 6. 구현 순서 (v1 범위 확정)

```
① 바닥 그리드 + 점유맵(이동 차단 포함) + 스폰존 예약   ← 데이터 모델 확정이 최우선
② 방문객 시스템 (전투 없음: 등장 → 구경 → 선물 → 퇴장)  ← 등장/퇴장/이동 인프라가 전투의 전제조건
③ 범용 FX 시트 제작 + 투닥 연출
④ 판정 로직(resolveBattle) + 드랍 수거
⑤ 보스/엘리트 티어(대형 스프라이트 + 전용 모션)
── 이후 고도화 ──
⑥ 축1 가구 버프 + 인접 시너지 + 소환 조건
⑦ 축2 부재중 타임랩스 리플레이
⑧ 축3 흔적 수거 + 낮/밤 + 날씨
⑨ 축4 줌/팔로우캠·포토 모드
```

각 단계마다: 순수 함수 단위 테스트 + 문서 갱신 + 절전/성능 확인(02 문서 §7).

## 7. 하지 말 것 (명시적 금지 목록)

1. **전투를 그리드 칸 단위로 구현하지 말 것** — 그리드는 점유·이동 데이터, 전투는 액터 레이어 연속 좌표.
2. **HP바·피격 출혈·죽음 연출 금지** — 투닥거림 톤(먼지구름·별·땀). 코지 정체성 유지.
3. **펫 종별 공격 모션을 전 종에 제작하지 말 것** — FX 오버레이 가림 연출로 해결. 전용 모션은 보스/엘리트만.
4. **연출 도중에 판정을 계산하지 말 것** — 시작 시점 시드 RNG로 선확정. 연출은 재생 전용.
5. **부재중 결과를 텍스트 로그만으로 끝내지 말 것** — 타임랩스 리플레이가 이 게임의 차별점. 단 스킵은 필수.
6. **배경(벽지/바닥재)에 그리드·배치 개념을 넣지 말 것** — 스킨 키 2개로 끝.
7. **스폰존에 가구 배치를 허용하지 말 것** — 판정·에디터 양쪽에서 차단.
8. **방 확장·친구 방·파견을 v1에 넣지 말 것** — 코어 루프(①~⑤) 완성이 먼저.
9. **가구별 상호작용·버프를 코드에 하드코딩하지 말 것** — 전부 카탈로그 데이터 주도.
